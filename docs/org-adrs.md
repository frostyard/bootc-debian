# Org-wide decisions (frostyard/core ADRs)

Some conventions are decided at org level. They are ADRs in
[frostyard/core](https://github.com/frostyard/core/tree/main/docs/adr).

These ADRs bind this repository. The list below says what each one binds
here, and where it lives in this repository.

## Decisions this repository follows

- [ADR-0018 — Org-wide agent instruction and knowledge surfaces](https://github.com/frostyard/core/blob/main/docs/adr/0018-org-wide-agent-instruction-and-knowledge-surfaces.md): [`AGENTS.md`](../AGENTS.md) is the canonical instruction file. `CLAUDE.md`, `GEMINI.md`, `.cursorrules` and [`.github/copilot-instructions.md`](../.github/copilot-instructions.md) are symlinks to it. A blocking review correction adds 1 record file under `.memory/corrections/`; the contract is [`.memory/README.md`](../.memory/README.md).
- [ADR-0019 — Repository governance as machine-readable policy with risk tiers](https://github.com/frostyard/core/blob/main/docs/adr/0019-governance-as-code-and-risk-tiers.md): every pull request declares a risk tier in the risk tier section of [`.github/pull_request_template.md`](../.github/pull_request_template.md).
- [ADR-0021 — SHA-pinned actions and least-privilege CI workflows](https://github.com/frostyard/core/blob/main/docs/adr/0021-sha-pinned-actions-and-least-privilege-ci.md): the workflows in [`.github/workflows/`](../.github/workflows/) pin every action to a full SHA with the version in a comment, set top-level `permissions: {}` or read-only permissions, and set `persist-credentials: false` on every checkout. [`tests/check-baseline.sh`](../tests/check-baseline.sh) checks all 3.
- [ADR-0025 — One docs/ tree per repository, in core's four-category shape](https://github.com/frostyard/core/blob/main/docs/adr/0025-consolidate-repository-docs-into-docs.md): all documentation lives in this [`docs/`](README.md) tree, in 4 categories, each with a `TEMPLATE.md`, plus the runbooks and the org ADR list.
- [ADR-0029 — ACMM conformance via canonical aliases](https://github.com/frostyard/core/blob/main/docs/adr/0029-acmm-conformance-via-canonical-aliases.md): the instruction-file aliases are relative symlinks to the canonical file, and the canonical file is the one that is edited. This repository has no tool payload of its own, so it carries no `.claude/skills` symlink.
- [ADR-0040 — Publish the repository settings contract](https://github.com/frostyard/core/blob/main/docs/adr/0040-publish-the-repository-settings-contract.md): the settings contract turns private vulnerability reporting on, and [`SECURITY.md`](../SECURITY.md) states the scope and which versions get fixes.
- [ADR-0043 — Pin repository tools in mise and name the verify gate](https://github.com/frostyard/core/blob/main/docs/adr/0043-pin-repository-tools-in-mise-and-name-the-verify-gate.md): [`mise.toml`](../mise.toml) and [`mise.lock`](../mise.lock) pin shellcheck, actionlint and jq, and `make verify` is the gate that runs them. The build's own dependencies are installed inside `debian:trixie` by [`build.sh`](../build.sh), so they are not mise tools.
- [ADR-0044 — Expose the make gate triad in every repository](https://github.com/frostyard/core/blob/main/docs/adr/0044-expose-the-make-gate-triad-in-every-repository.md): the [`Makefile`](../Makefile) has the `verify`, `check` and `ci` targets; `ci` and `check` both run `verify`.
- [ADR-0055 — Publish Debian packages through the apt-publisher single writer](https://github.com/frostyard/core/blob/main/docs/adr/0055-publish-debian-packages-through-the-apt-publisher.md): this repository builds and releases the packages and publishes nothing itself. The `Request APT publication` job in [`build.yml`](../.github/workflows/build.yml) sends a `publish-deb` request, and the `~debNN` version marker that [`build.sh`](../build.sh) puts in each version routes the packages to a codename. The scheme is in [design/overview.md](design/overview.md).
- [ADR-0056 — The APT publisher triggers image rebuilds after packages are live](https://github.com/frostyard/core/blob/main/docs/adr/0056-rebuild-images-after-apt-publication.md): after a publication is read back, apt-publisher dispatches a build to frostyard/snosi, whose images install these packages. The release job in [`build.yml`](../.github/workflows/build.yml) says so, and [design/overview.md](design/overview.md) has the flow.
- [ADR-0059 — Publish image-only packages in a separate APT component](https://github.com/frostyard/core/blob/main/docs/adr/0059-publish-image-only-packages-in-a-separate-apt-component.md): `bootc` and `libostree-1-1` go to the `image` component of `trixie` and `forky`, because `libostree-1-1` replaces Debian's package of the same name. The request in [`build.yml`](../.github/workflows/build.yml) names no component: apt-publisher places the packages in the component this repository is registered for. [design/overview.md](design/overview.md) has the rules for the component and for the versions that moved.
- [ADR-0068 — Label pull requests that touch high-risk paths](https://github.com/frostyard/core/blob/main/docs/adr/0068-label-pull-requests-that-touch-high-risk-paths.md): [`.github/risk-paths.json`](../.github/risk-paths.json) lists the paths, including [`build.sh`](../build.sh), [`download/`](../download/) and the workflows, and [`.github/workflows/risk-paths.yml`](../.github/workflows/risk-paths.yml) calls core's `pr-triage.yml` workflow, which adds the `level:L1` to `level:L4` label and `risk:high` at L1 and L2 (core ADR-0078).
- [ADR-0071 — Hold every code repository to one baseline](https://github.com/frostyard/core/blob/main/docs/adr/0071-hold-every-code-repository-to-one-baseline.md): this repository carries the baseline checklist ([spec](https://github.com/frostyard/core/blob/main/docs/specs/repository-baseline.md)), checked by [`tests/check-baseline.sh`](../tests/check-baseline.sh) and its negative tests. It has a [`LICENSE`](../LICENSE) (MIT), a [Dependabot config](../.github/dependabot.yml) and a [`ci.yml`](../.github/workflows/ci.yml) that runs `make ci` on pull requests. It has no `CODEOWNERS`.
- [ADR-0072 — Write every README to one standard](https://github.com/frostyard/core/blob/main/docs/adr/0072-write-every-readme-to-one-standard.md): [`README.md`](../README.md) is the front page for a package repository (kind `packaging`, at most 1000 words). The flow, the rules and the runbooks live in this [`docs/`](README.md) tree.
- [ADR-0073 — Let CI run the `make ci` targets as separate jobs](https://github.com/frostyard/core/blob/main/docs/adr/0073-let-ci-run-the-make-ci-targets-as-separate-jobs.md): CI may split `make ci`. This repository runs it in one job, [`ci.yml`](../.github/workflows/ci.yml), and splits nothing.
- [ADR-0075 — Group Dependabot updates and sync skills once a day](https://github.com/frostyard/core/blob/main/docs/adr/0075-batch-routine-pull-requests.md): each entry of [`.github/dependabot.yml`](../.github/dependabot.yml) has 1 `patterns: ["*"]` group, so Dependabot opens at most 1 version-update PR for each ecosystem and run; security updates stay 1 PR each.
- [ADR-0081 — Store each correction in a file of its own](https://github.com/frostyard/core/blob/main/docs/adr/0081-store-each-correction-in-a-file-of-its-own.md): amends ADR-0018 and ADR-0071 in part. Each correction record is 1 file in [`.memory/corrections/`](../.memory/README.md), in canonical form; a record is never removed or renamed.

## Not applicable here

- [ADR-0012 — svu-derived versions, make bump, and the rolling dev prerelease](https://github.com/frostyard/core/blob/main/docs/adr/0012-svu-versioning-and-rolling-dev-prerelease.md) and [ADR-0053 — Name the svu config file `.svu.yml`](https://github.com/frostyard/core/blob/main/docs/adr/0053-name-the-svu-config-svu-yml.md): this repository has no Go module and its versions come from the upstream releases, not from `svu`. The scheme is in [design/overview.md](design/overview.md).
- [ADR-0070 — Build tool docs sites with ProperDocs and MaterialX on GitHub Pages](https://github.com/frostyard/core/blob/main/docs/adr/0070-build-tool-docs-sites-with-materialx-on-github-pages.md): this is a package repository, not a user-facing tool, and it has no docs site. The documentation is this `docs/` tree.

When you change behavior that one of these ADRs covers, update or supersede the
ADR in frostyard/core first.
